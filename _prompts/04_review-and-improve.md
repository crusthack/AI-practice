# 프롬프트: 기존 practice 검토 및 고도화

> 이 파일 전체를 Claude Code에 붙여넣어 사용합니다.  
> `[변수 입력]` 섹션만 실제 값으로 채운 뒤 전달하세요.

---

## [변수 입력]

```
TARGET_PRACTICE = practice-Win32             # 검토할 디렉토리
REVIEW_SCOPE    = all                        # all | phase:<Phase폴더명> | module:<모듈폴더명>
FOCUS           = code,docs,tasks            # 검토 항목 (쉼표로 조합)
                                             #   code  : 코드 품질·버그·컴파일 오류
                                             #   docs  : README·LEARNING_GUIDE·CLAUDE 완성도
                                             #   tasks : 미완성 확장 과제 구현
```

---

## 에이전트 지시사항

위 변수들을 사용해 `TARGET_PRACTICE` 디렉토리를 검토하고 개선합니다.

### Phase 0: 현황 파악

1. `README.md`, `CLAUDE.md`, `LEARNING_GUIDE.md` 를 읽고 전체 구조를 파악합니다.
2. `REVIEW_SCOPE` 에 따라 검토 범위를 결정합니다.
   - `all` : 전체 모듈
   - `phase:<이름>` : 해당 Phase 폴더만
   - `module:<이름>` : 해당 모듈만
3. 각 모듈의 소스 파일(`main.cpp` 또는 `Program.cs`)을 읽습니다.

---

### FOCUS: code (코드 품질 검토)

**C++ 모듈에서 확인할 항목:**

| 항목 | 확인 방법 |
| --- | --- |
| 컴파일 오류 | `MSBuild` 실행, 오류 있으면 수정 |
| 리소스 누수 | 핸들 `CloseHandle`, 소켓 `closesocket`, COM `Release` 누락 여부 |
| 오류 처리 부재 | Win32 API 반환값 미검사 항목 |
| 주석 없는 복잡 로직 | 의도가 불분명한 비트 연산, 포인터 산술 등 |
| 하드코딩 상수 | 매직 넘버 → `constexpr` 또는 `#define` 으로 교체 |

**C# 모듈에서 확인할 항목:**

| 항목 | 확인 방법 |
| --- | --- |
| 빌드 오류 | `dotnet build` 실행, 오류 있으면 수정 |
| `IDisposable` 미해제 | `using` 블록 누락 여부 |
| 동기 IO | `Stream.Read` → `ReadAsync` 등 비동기 전환 |
| `async void` 남용 | 이벤트 핸들러 외에는 `async Task` 사용 |
| Nullable 경고 | `#nullable enable` 하 `?` 누락 |

개선 후 해당 파일을 수정하고 빌드를 다시 확인합니다.

---

### FOCUS: docs (문서 완성도 검토)

**README.md 확인:**
- [ ] 모든 모듈이 목차에 있는가
- [ ] 빠른 시작 명령이 실제로 동작하는가
- [ ] Phase·모듈 수가 실제 폴더 수와 일치하는가

**LEARNING_GUIDE.md 확인:**
- [ ] 모든 모듈에 교안이 있는가
- [ ] 교안에 목표·관찰·핵심 API·확장 과제 네 항목이 모두 있는가
- [ ] API 이름에 오타나 잘못된 정보가 없는가

**CLAUDE.md 확인:**
- [ ] Phase별 진행 현황 표가 실제 상태와 일치하는가
- [ ] 초기화 템플릿이 현재 모듈들과 일관된가
- [ ] 주의 사항이 현재 코드 상태를 반영하는가

누락·불일치 항목을 찾아 파일을 수정합니다.

---

### FOCUS: tasks (확장 과제 구현)

1. `LEARNING_GUIDE.md` 에서 각 모듈의 확장 과제를 읽습니다.
2. 해당 모듈의 소스 파일을 읽고 확장 과제 구현 여부를 확인합니다.
3. 미구현된 확장 과제 중 **난이도가 낮고 핵심 개념을 보강하는 것** 1~3개를 선정합니다.
4. 선정한 과제를 소스 파일에 추가 구현합니다.
   - 기존 코드 아래에 구분선(`// ─── 확장: <과제명> ───`)으로 구분합니다.
   - 구현 후 빌드 성공 여부를 확인합니다.
5. `LEARNING_GUIDE.md` 해당 모듈의 확장 과제 항목에 `(구현 완료)` 를 표시합니다.

---

### Phase 마지막: 검토 리포트 작성

검토 완료 후 아래 형식으로 결과를 출력합니다 (파일로 저장하지 않고 콘솔 출력).

```
=== 검토 리포트: TARGET_PRACTICE ===

[코드] 수정된 파일: (목록)
[코드] 발견된 주요 문제: (요약)

[문서] 수정된 파일: (목록)
[문서] 발견된 주요 불일치: (요약)

[과제] 구현된 확장 과제: (모듈명 + 과제명 목록)

다음 개선 권고사항:
1. ...
2. ...
```

## 품질 기준

- `code` 포함 시: 모든 모듈 빌드 성공
- `docs` 포함 시: README·LEARNING_GUIDE·CLAUDE 불일치 없음
- `tasks` 포함 시: 최소 1개 확장 과제 구현 완료
- 리포트 출력 완료
